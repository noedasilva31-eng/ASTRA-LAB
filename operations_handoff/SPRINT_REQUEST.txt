> # VISION PRODUIT
>
> ASTRA doit devenir un **DESK autonome de recherche et de paper/live trading spécialisé dans les marchés Solana rapides et memecoins**.
>
> L'architecture doit clairement séparer deux chemins.
>
> ### HOT PATH
>
> `flux Solana → événements DEX/pools/swaps → features temps réel → signaux validés → Risk déterministe → paper/exécution`
>
> Ce chemin doit rester rapide. Il ne doit pas dépendre d'un raisonnement LLM lourd, d'un export JSON ou d'une reconstruction complète avant de pouvoir réagir.
>
> ### RESEARCH / MEMORY PATH
>
> `données brutes → provenance → historique → données on-chain/sociales → datasets → recherche → backtests → agents R&D → stratégies candidates`
>
> Ce chemin peut effectuer les analyses lourdes.
>
> Les deux chemins doivent partager une mémoire vérifiable sans que le Research Path bloque le Hot Path.
>
> ---
>
> # PRIORITÉ DU PROCHAIN SPRINT
>
> Après le correctif `live_memory`, consacre l'essentiel du temps à de la **progression fonctionnelle visible**, pas à produire des micro-versions.
>
> Avance autant que possible, selon les dépendances, sur :
>
> **DEX ciblés → pools → swaps → liquidité/événements marché → wallets/holders/bundles → feature store temporel → paper trading → journal décisionnel.**

> # DEX / POOLS / SWAPS
>
> ASTRA doit progressivement pouvoir reconstruire un événement vérifiable de la forme :
>
> `wallet → swap → token A → token B → montants → pool → DEX → frais → slot → transaction → brut source`
>
> avec :
>
> - provenance ;
> - ordre temporel ;
> - couverture connue ;
> - intégrité vérifiable ;
> - replay hors réseau ;
> - reconstruction déterministe.
>
> Prévois une architecture extensible pour plusieurs protocoles plutôt qu'un décodeur monolithique.
>
> Les protocoles réellement pris en charge doivent être explicitement identifiés. Une instruction non comprise doit rester comptabilisée plutôt qu'être silencieusement interprétée.
>
> Pour ce sprint, privilégie **un petit nombre de protocoles réellement supportés et bien testés** plutôt qu'une fausse couverture générale.
>
> ---
>
> # MEMECOIN / ON-CHAIN INTELLIGENCE
>
> ASTRA est destiné à travailler sur des marchés rapides.
>
> Construis progressivement les primitives nécessaires pour analyser :
>
> - créations de tokens/pools ;
> - événements de lancement/migration lorsque observables ;
> - swaps ;
> - liquidité ;
> - accélération/décélération du volume ;
> - variations rapides de prix ;
> - wallets ;
> - candidats smart-money ;
> - historique comportemental des wallets ;
> - holders ;
> - concentration des holders ;
> - relations entre wallets ;
> - clusters/graphes de wallets de type bubble-map ;
> - financements communs ou relations observables entre wallets ;
> - bundles lorsque les données disponibles permettent réellement de les identifier ;
> - comportement du deployer ;
> - retraits/variations de liquidité ;
> - primitives de détection/analyse de risque et de rug.
>
> Ces analyses doivent produire **des observations et des preuves mesurables**, pas des scores arbitraires présentés comme des certitudes.
>
> Conserve la provenance permettant de remonter aux événements ayant produit chaque indicateur.
>

> # SOCIAL / X / KOL / META
>
> ASTRA devra pouvoir intégrer des sources publiques externes pour comprendre l'attention autour des memecoins.
>
> Prépare une architecture permettant d'ajouter :
>
> - tracking de comptes publics X/KOL ;
> - mentions de tokens/tickers/contracts ;
> - chronologie des mentions ;
> - fréquence des mentions ;
> - vitesse de propagation ;
> - social velocity ;
> - historique observable après certaines mentions ;
> - émergence de metas/narratives ;
> - association tokens ↔ narratives ;
> - évolution d'une meta ;
> - corrélation temporelle social ↔ wallets ↔ swaps ↔ liquidité ↔ prix.
>
> Ne consomme pas inutilement le quota à implémenter une grosse intégration X si les accès/API nécessaires sont absents.
>
> En revanche, conçois les **interfaces temporelles, couverture et provenance** nécessaires pour intégrer ces sources plus tard dans la même timeline que les données on-chain.
>
> Une absence de couverture sociale ne doit jamais être interprétée comme une absence d'activité sociale.
>

>

> # AGENTS R&D / AMÉLIORATION DU « CERVEAU »
>
> À terme, les agents R&D devront pouvoir :
>
> `observer → détecter une hypothèse → la formaliser → développer une feature/stratégie candidate → backtester → tenter de la falsifier → paper trade → mesurer → conserver ou rejeter`
>
> Un Developer Agent pourra donc produire du code candidat, mais **aucun agent ne doit pouvoir remplacer directement le cerveau opérationnel ou contourner les gates de validation**.
>
> Prépare progressivement le modèle :
>
> `brain actuel → candidate → replay → backtest → hors-échantillon/stress → paper → comparaison → promotion ou rejet`
>
> avec :
>
> - versioning ;
> - reproductibilité ;
> - provenance du code/configuration ;
> - métriques ;
> - rollback ;
> - séparation candidate/production ;
> - impossibilité pour un candidat de s'auto-promouvoir en LIVE.
>
> Les agents ne doivent pas pouvoir augmenter arbitrairement leurs propres limites de risque.
>

> # APPRENTISSAGE APRÈS LES SESSIONS PAPER
>
> ASTRA devra pouvoir fonctionner pendant des sessions paper prolongées, par exemple **10 heures**, en conservant pour chaque décision :
>
> `informations réellement disponibles à T → couverture → features → analyses/signaux → décision Risk → paper trade → résultat futur`
>
> Après une session, les futurs agents Data/Quant/Research/Critic devront pouvoir analyser :
>
> - ce qui a fonctionné ;
> - ce qui a échoué ;
> - quels signaux étaient inutiles ;
> - quelles combinaisons semblent intéressantes ;
> - quelles données manquaient ;
> - quelles hypothèses méritent d'être testées ;
> - quelles modifications candidates devraient être développées.
>
> **Aucun look-ahead.**
>
> Une décision historique doit pouvoir être rejouée avec uniquement les informations réellement disponibles au moment où elle a été prise.
>
> Utilise directement pour cela les mécanismes existants de brut, couverture, provenance, replay et reconstruction.
